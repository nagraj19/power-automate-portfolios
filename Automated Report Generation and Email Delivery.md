# Email-Triggered Power BI Report Export Using Power Automate

## 1. Project Overview

This project demonstrates how to automate Power BI report export and email distribution using Microsoft Power Automate and Outlook.

Instead of running the flow at a fixed time, the workflow starts when a new email arrives in a specified Outlook inbox. The email can be generated by a Power BI report subscription after the report refresh process has completed.

Once the expected email arrives, Power Automate starts the export workflow, generates the Power BI report file, creates the output file, retrieves its content, and sends the report through email.

The workflow also includes separate **Success** and **Failure** scopes to organize successful execution and error handling.

## 2. Project Objectives

- Trigger Power Automate when a specific email arrives in Outlook.
- Use a Power BI subscription email as a signal that a report is ready for processing.
- Export a Power BI report to a supported file format.
- Create and retrieve the generated report file.
- Send the exported report to the intended recipients.
- Organize the flow using Scope actions for better error handling.
- Compare time-based automation with email-triggered automation.

## 4. Power Automate Workflow

The flow begins with the **When a new email arrives (V3)** trigger. The report export and delivery actions are grouped inside a Scope, followed by separate Success and Failure scopes.

![Email-Triggered Power BI Report Export Flow](Screenshot/FLow%20flow.png)

### Workflow steps

1. **When a new email arrives (V3)**  
   Power Automate monitors the configured Outlook mailbox and starts the flow when a matching email arrives.

2. **Scope – Main Process**  
   The report export and email delivery actions are grouped into a single scope.

3. **Export To File for Power BI Reports**  
   The flow requests an export of the configured Power BI report using the selected format and settings.

4. **Create file**  
   The exported report is saved to the configured file location.

5. **Get file content**  
   The flow retrieves the generated file content for use as an email attachment.

6. **Send Email (V3)**  
   The exported report is sent to the configured recipients.

7. **Success scope**  
   This scope can contain logging, notifications, or other actions to perform after successful processing.

8. **Failure scope**  
   This scope can contain error logging or failure notifications when the main process fails, provided its run-after settings are configured appropriately.

## 5. Why Use an Email Trigger?

A time-based flow runs according to a schedule. An email-triggered flow starts when a matching email is received.

In this project, the intended design is to use a Power BI subscription email as the signal to begin the export workflow. This helps coordinate report distribution with the report-refresh process rather than relying only on a fixed schedule.

For example, a Power BI report subscription can be configured to send an email according to its subscription settings. Power Automate can monitor for that notification and start the export process.

**Important:** An email trigger does not independently verify that the underlying Power BI semantic model has refreshed successfully. The workflow relies on the subscription email being sent at the appropriate point. If explicit refresh confirmation is required, add a refresh-status check before exporting the report.

## 6. Time-Based Trigger vs. Email-Based Trigger

| Feature | Time-Based Trigger | Email-Based Trigger |
|---|---|---|
| Trigger condition | A configured schedule | A matching email arrives |
| Execution timing | Fixed or recurring time | When the email is received |
| Dependency | Schedule and preceding processes | Email notification and trigger conditions |
| Refresh coordination | Must be planned around refresh timing | Can react to a subscription notification |
| Risk of running too early | Possible if refresh is delayed | Reduced if the notification is sent at the correct stage |
| Handling delayed events | Depends on the schedule and flow design | Depends on mailbox, trigger configuration, and event handling |
| Best suited for | Predictable, time-driven processes | Event-driven workflows linked to a notification |

### When should you use each approach?

**Use a time-based trigger when:**

- The report must be generated at a specific time.
- The refresh schedule is predictable.
- The process does not depend on a notification from another system.

**Use an email-based trigger when:**

- A subscription or another process sends an email when the report is ready.
- You want the next stage to react to that event.
- The workflow should not rely solely on a fixed time.

## 7. How the Power BI Subscription Fits In

The intended end-to-end process is:

1. The Power BI semantic model or data source refreshes.
2. The Power BI subscription sends a notification email according to its configuration.
3. Outlook receives the email.
4. Power Automate detects the matching email.
5. The flow exports the configured Power BI report.
6. The flow creates the output file and retrieves its content.
7. The exported report is emailed to the final recipients.

This design separates the report-readiness notification from the report-export and distribution process.

For greater reliability, configure the subscription to notify at the appropriate stage, and add a refresh-status check if the workflow requires explicit confirmation that the latest refresh succeeded. Ensure the export action uses the intended report, filters, and permissions.

## 8. Error Handling with Success and Failure Scopes

The flow includes separate Success and Failure scopes to make execution easier to monitor and troubleshoot.

### Success scope

The Success scope can be configured to:

- Record a successful run.
- Send a completion notification.
- Log the generated report file name and execution details.

Configure its **Run after** behavior so it runs only when the main processing scope succeeds.

### Failure scope

The Failure scope can be configured to:

- Record error details.
- Notify the flow owner.
- Capture failed-action and execution information.
- Support investigation and recovery.

Configure its **Run after** settings to run when the main processing scope has failed, timed out, or otherwise meets the selected failure conditions.

## 9. Security and Reliability Considerations

- **Filter incoming emails:** Configure the trigger using the expected sender, subject, mailbox, or other available properties.
- **Prevent unrelated triggers:** Ensure unrelated emails do not initiate report exports.
- **Validate report readiness:** Confirm that the notification corresponds to the intended report and refresh event.
- **Check export permissions:** Ensure the flow connection has the required access to the Power BI report.
- **Validate output files:** Check that the generated attachment contains the expected content and uses the correct format.
- **Prevent duplicate processing:** Consider how repeated or duplicate notification emails should be handled.
- **Configure error handling:** Monitor failed runs and notify the flow owner when required.
- **Protect confidential data:** Use appropriate access controls for reports, files, mailboxes, and recipients.
